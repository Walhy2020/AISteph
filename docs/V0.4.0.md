# v0.4.0 录音工作台与在线播放

## 本阶段目标

把 PC 管理台收敛为单一录音工作台。用户可以选择麦克风、录音、停止保存，并在同一页面找到和播放历史录音。文字、文章链接和文件收录能力继续保留为底层接口，但不在页面展示。

## 已实现

- 管理台只展示录音设备、录音状态、录音操作和录音资料库。
- 页眉、服务状态和页脚显示 v0.4.0。
- 统计录音总数、累计有效时长和等待确认数量。
- `/api/inbox?type=audio` 返回录音条目及进程级签名播放地址。
- `/api/audio/:sourceId` 只读取已经登记且位于 `./data/audio` 内的音频。
- 播放接口支持 GET、HEAD、标准 Range 和后缀 Range。
- 浏览器播放器使用 `preload="metadata"`，避免打开页面时读取全部音频。
- 开始播放新录音时会暂停其他录音，避免多个声音同时播放。
- 播放失败时在对应卡片显示错误状态。
- 原文字、文章链接和文件收录 API 及命令行入口保持可用。

## 页面边界

当前页面不再展示以下入口：

- 文字收录。
- 文章链接收录。
- 本地文件上传。
- 多类型资料筛选。

这些能力没有从服务端删除，后续恢复多来源界面时可以继续复用。

## 安全与隐私

- 服务继续只监听 `127.0.0.1`。
- API 查询继续要求本地进程令牌。
- 播放地址使用 HMAC-SHA256 签名，不把通用 API 令牌直接放入 URL。
- 播放前校验记录类型、记录 ID、文件存在性和目录边界。
- 无效或越界 Range 返回 416，并携带实际文件长度。
- 音频响应禁用缓存、禁止 MIME 嗅探并禁止发送 Referrer。
- 日志记录接口、状态码、耗时和错误元数据，不记录音频内容。

## 性能策略

- 录音列表最多读取 200 条，避免首屏无限增长。
- 音频采用流式读取，不把完整文件加载到 Node.js 内存。
- Range 支持浏览器定位和分段缓冲。
- `preload="metadata"` 仅预取播放器所需元数据。

## 自动化验收

- 完整音频返回 200。
- HEAD 返回文件长度且无响应正文。
- 字节 Range 与后缀 Range 返回 206。
- 无效范围返回 416。
- 无效签名返回 403。
- 非音频记录返回 404。
- 目录逃逸返回 403。
- 非 GET/HEAD 方法返回 405。
- 页面包含录音工作台和播放器，不包含旧收录入口。
- 原文字、链接和文件接口回归测试继续通过。

## 暂不包含

- 音频原生理解或转写分析。
- 新音频心跳监控和 Codex 自动唤醒。
- 分析结论确认界面。
- 确认后写入正式知识库。
- 移动端、系统托盘和开机启动。

下一阶段将围绕“新录音发现 → 通知 Codex 分析 → 结论待确认”推进。
